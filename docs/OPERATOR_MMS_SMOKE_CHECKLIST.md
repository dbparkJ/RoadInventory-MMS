# 실제 MMS 운영자 흐름 스모크 체크리스트

이 체크리스트는 합성 데이터와 `jsdom`만으로 확인할 수 없는 파노라마, 점군, SHP 저장의 실제 연결을 배포 전에 검증한다. 테스트 전용 데이터 복사본에서 실행하고 원본 MMS 폴더는 변경하지 않는다.

## 사전 조건

- [ ] 파노라마 영상과 점군이 같은 프레임에서 열리는 실제 MMS 데이터셋을 등록했다.
- [ ] 대상 범위에 완료 상태의 검출 run이 하나 이상 있다.
- [ ] 교통표지판과 지주를 저장할 쓰기 가능한 Point 레이어가 있다.
- [ ] 신규·수정 피처를 확인할 수 있도록 테스트 전 레이어 revision과 피처 수를 기록했다.

## A. 검수 작업 시작과 복원

- [ ] 한 프레임 또는 범위를 선택하고 `새 검수 작업`을 연다.
- [ ] 완료 run, 대상 Point 레이어, 후보 source를 선택해 `검수 작업 시작`을 누른다.
- [ ] 상단 단계가 `범위 → 후보 → 처리 → QA → 완료` 순서로 표시되고 작업 큐에 후보가 생성된다.
- [ ] 후보를 선택하면 지도·파노라마·점군이 후보 프레임으로 이동한다.
- [ ] 한 후보를 `완료`, 다른 후보를 `오검출` 또는 `현장조사`로 처리하고 진행률 변화를 확인한다.
- [ ] 완료 항목의 `다시 확인`을 누르면 즉시 다시 처리할 수 있다.
- [ ] 브라우저를 새로고침해도 선택한 검수 작업, 작업 큐 필터와 현재 위치를 이어서 사용할 수 있다.
- [ ] 후보가 0개인 범위를 별도로 만들었을 때도 QA를 실행하면 서버의 완료 조건에 따라 작업을 완료할 수 있다.
- [ ] 후보 생성 중 다른 데이터셋으로 이동해도 이전 데이터셋의 작업이 새 화면에 나타나거나 재시도 대상으로 남지 않는다.

## B. 교통표지판 bbox 수동 추가

- [ ] 검수 후보를 연 상태에서 객체 템플릿을 `교통표지판`으로 선택하고 대상 레이어와 필수 속성을 지정한다.
- [ ] `M` 또는 `파노라마 bbox 시작`을 누르고 실제 표지판을 드래그한다.
- [ ] 마우스를 놓는 즉시 파노라마 안에 `3D 위치 계산 중` 상태가 표시된다. 별도의 계산 버튼은 필요하지 않다.
- [ ] 점군 준비가 늦을 때 재시도 횟수와 상태가 보이고 준비 후 자동으로 계산을 계속한다.
- [ ] 임시 제안점이 저장 전부터 파노라마와 점군에 같은 위치로 표시된다.
- [ ] `bbox 다시 그리기`와 실패 시 `계산 재시도`가 동작한다.
- [ ] `확인` 또는 `저장 후 다음`으로 저장하면 Point 피처가 한 번만 생성되고 현재 후보는 `수동 추가`로 연결된다.
- [ ] 저장 뒤 레이어 revision과 피처 수가 증가하고 새 피처의 필수 속성과 provenance를 확인했다.
- [ ] 파노라마를 새 창으로 분리한 상태에서도 bbox 드래그 → 계산 상태·재시도 확인 → 임시 제안점 확인 → `확인` 또는 `저장 후 다음`까지 분리 창 안에서 완료되고, 메인 창의 레이어와 검수 항목에 저장 결과가 즉시 반영된다.
- [ ] bbox 제안이 준비된 뒤 같은 프레임의 다른 검수 후보를 선택하면 새 후보를 잘못 `수동 추가`로 완료하지 않고, 원래 후보와의 연결이 바뀌었다는 안내가 표시된다.

## C. 지주 B → B 신규·수정

- [ ] `표지 지주` 템플릿에서 생성을 시작하고 점군의 지주 몸체점을 클릭한다.
- [ ] 첫 번째 `B`에서 바닥점이 계산되고 저장 전 임시점이 파노라마와 점군에 표시된다.
- [ ] 두 번째 `B`에서 신규 Point가 저장되며 지면 높이와 XYZ 속성이 geometry와 일치한다.
- [ ] 지주 점군이 바닥까지 닿지 않는 대상을 반복해, 임의 복셀 높이가 아니라 합성 지면 교차점에 저장되는지 확인한다.
- [ ] 기존 지주 Point를 선택해 `지주 하단 재산출` → 새 몸체점 → `B` → `B` 순서로 위치를 수정한다.
- [ ] 수정 후 피처 수는 유지되고 선택 피처의 위치·파생 속성·revision이 변경되며 검수 후보는 `수정 완료`로 연결된다.
- [ ] 설정에서 바닥점 마커 색상과 크기를 바꾸면 파노라마와 점군의 임시 마커에 모두 반영된다.
- [ ] 바닥점 제안이 준비된 뒤 같은 프레임의 다른 검수 후보나 다른 검수 작업으로 전환하면 두 번째 `B`가 새 후보를 잘못 완료하지 않고, 현재 항목에서 산출을 다시 시작하라는 안내가 표시된다.

## D. QA와 완료 차단

- [ ] 미처리 후보가 남아 있을 때 완료가 비활성화되고 차단 이유가 한국어로 표시된다.
- [ ] 모든 후보 처리 후 `Q` 또는 `QA`에서 검사를 실행한다.
- [ ] QA 오류가 있는 상태에서는 완료할 수 없다. 오류 데이터를 수정하고 QA를 다시 실행하면 오류가 해소된다.
- [ ] 경고를 무시할 때 3자 이상의 사유가 필요하고 그 사유가 다시 열었을 때 유지된다.
- [ ] QA 후 피처를 한 번 더 수정하면 QA가 오래된 상태로 표시되고 재실행 전까지 완료할 수 없다.
- [ ] 모든 조건을 만족하면 `검수 작업 완료`가 성공하고 새 편집은 차단된다.
- [ ] QA 실행 중 다른 검수 작업으로 바꿔도 이전 작업의 QA 목록과 완료 조건이 새 작업 화면을 덮어쓰지 않는다.

## E. 결과·안정성

- [ ] JSON, CSV, Markdown 보고서와 편집 결과 ZIP을 내려받아 작업 수, 판정 수, 레이어 revision이 화면과 일치하는지 확인한다.
- [ ] Active-learning 기능이 허용된 서버에서만 해당 ZIP 메뉴가 보이며, 내려받기가 자동 학습이나 모델 배포를 시작하지 않는지 확인한다.
- [ ] 내보낸 파일에 서버 절대 경로, 작업자 개인식별정보 또는 스프레드시트 수식으로 실행될 값이 없는지 점검한다.
- [ ] 점군 창을 5분 이상 다른 창 뒤에 둔 뒤 돌아와 이동·회전·프레임 전환이 멈춤 없이 동작한다.
- [ ] 저장 직후 앱을 재시작해도 피처와 검수 판정이 서로 같은 최종 상태로 복구된다.

실패 항목에는 데이터셋·프레임·검수 작업 ID, 화면 캡처, 브라우저 콘솔과 서버 로그 시각을 함께 기록한다.
